Result: all 5 board Python API/storage tests passed. The POSIX-only test used
resource.RLIMIT_FSIZE and ignored SIGXFSZ in the test process, with SQLite files in a

returned "disk I/O error", AppState counted one failed event write, and the worker
reader continued. The test restored the original resource limit and signal handler,
then a later event persisted successfully and the storage status recovered.

The test changed no filesystem quota or system setting and did not fill the board
filesystem. This is not evidence of behavior under actual ENOSPC or sustained low disk.
The Windows host suite skips this POSIX-only test; the complete suite ran on RK3576.
