# P1 acceptance report — first board-side model loop

- **Date:** 2026-11-05
- **Board:** KICKPI K7 / RK3576 / Ubuntu 24.04.3 aarch64
- **Status:** P1 detection-to-event/API runs passed on still and moving sample video; full P1 acceptance remains open.

## What ran

The project YOLOv8n ONNX graph was converted in the isolated Ubuntu 22.04 x86-64 WSL2 environment with RKNN-Toolkit2 2.0.0b0, targeting `rk3576` in non-quantized `fp` mode. The resulting 8,317,332-byte `.rknn` model was copied into the board's project-only `.work` directory. The application, native build, RKNN C Runtime, video worker, event storage, and HTTP service ran on the RK3576; the host did not provide inference hardware or runtime.

The board worker loaded a 640×640, three-channel input and nine YOLO outputs. A 16-frame, 4-FPS MP4 was generated by repeating the Model Zoo `bus.jpg`. The board processed all 16 frames and reported 80 detections. The tracker produced five initial `enter` events (one bus and four people); the service persisted them in SQLite and returned them through `/api/events`. `/api/health` reported `completed`, worker exit code 0, and event count 5. The dashboard server bound to `127.0.0.1` only.

The test also exposed upstream diagnostic text on worker stdout. The integration now sends those `printf` diagnostics to stderr, preserving JSONL metrics/events on stdout. The board was rebuilt after that change; CTest passed 2/2 and Python API/storage tests passed 2/2.

A second run used the first 150 frames of the OpenCV sample `vtest.avi`, encoded as a 768×576, 10-FPS MP4. The full board service completed with exit code 0, decoded 150 frames, processed 130, dropped 20, produced 1,033 detections, and persisted 42 events. Health, metrics, and events endpoints returned HTTP 200. This exercises moving pedestrian/vehicle video through RKNN inference, drawing, event evidence capture, storage, and API output. It is not a labeled accuracy test or proof of stable identity tracking: all 42 events were `enter` events with 42 unique IDs, and two low-confidence `skis` predictions overlapped a pedestrian's lower body/feet in an inspected evidence frame.

The first dynamic run showed likely track fragmentation, so the tracker was revised to extrapolate box centers from recent motion, gate matches by class and area, and assign candidate matches globally one-to-one using IoU and center distance. A controlled board comparison compiled the previous greedy-IoU tracker and the candidate separately, then ran each three times on the same model and all 150 frames with confidence 0.25, full-frame ROI, and queue capacity 150. Every run decoded/processed 150/150 frames, dropped 0, and reported 1,194 detections. The old tracker emitted 33 enter events each run (29 person, two skis, one car, one truck); the candidate emitted 29 each run (25 person, two skis, one car, one truck). The candidate therefore emitted four fewer enter events per run, a repeatable 12.1% reduction under this input. There is no ground-truth identity annotation, so this may indicate fewer track splits or incorrect merges; it is not an accepted accuracy improvement.

The ROI event layer now confirms entry and exit after a configurable number of consecutive processed frames (default two), emits one dwell event after a configurable media-time threshold (default 5 seconds), and reports confirmed occupancy plus cumulative entries. Dwell uses increasing OpenCV media timestamps when available, with nominal-FPS and decode-time fallbacks for invalid or regressing timestamps. Enter and dwell records use state `active`; leave records use `closed`. Track expiry while still inside removes the track from occupancy without emitting a synthetic leave. The dashboard shows event type/state, track, confidence, occupancy, and evidence.

The repeated-still clips validate model loading, tensor handling, postprocessing, and bounded queue behavior. The moving sample exercises the dynamic-video pipeline and verifies that event transitions, counts, timestamps, evidence capture, SQLite persistence, and API retrieval work together. It does not establish event precision or identity correctness without annotations; two `skis` predictions persist on the pedestrian scene. Four leave events were observed, while three confirmed tracks remained inside the configured ROI at clip end. The 150-frame queue prevents drops for the controlled comparison but creates multi-second p95 delays, so it is not the real-time configuration. Neither run validates labeled accuracy, identity continuity, peak throughput, or target-camera behavior.

## Limits and remaining P1 gates

- The board reports RKNN Runtime 2.0.0b0 and driver 0.9.7. One repeated-still probe recorded shared NPU/IOMMU interrupt counts increasing during the worker and remaining flat during an idle comparison. A later moving-video sample also increased during the worker, but a same-boot read several minutes later was lower than the captured value. This discrepancy is unresolved; `/dev/rknpu*` nodes are absent and the runtime-to-device path is not traced. No verified utilization, per-core utilization, or frequency-scaling claim is made; the devfreq `load` string remained unchanged during idle.
- The same-input comparison covers only six single frames. It shows raw low-score class and score-sum differences and a threshold-sensitive detection-set difference on the bus sample at confidence 0.345. Broader model-output validation and labeled detection metrics remain open. The Toolkit2 conversion warned that the ONNX opset is 12 while 19 is recommended.
- Dynamic video and all three ROI transition types were exercised with one local sample clip, but event precision and identity continuity are unvalidated without ground-truth annotations. `leave` requires stable outside observations; if a tracker ID expires while inside, occupancy is decremented without a leave event. The 150-frame comparison queue created multi-second latency and does not represent the live queue-capacity-1 configuration. Physical camera, full MPP/RGA worker integration, representative INT8 calibration, and labeled event/tracker evaluation remain open. Short RTSP and recovery checks passed; a 24-hour soak is outside this project's acceptance scope, and the earlier exploratory run stopped before its configured duration. Isolated MPP/RGA probes are documented in [P2_ACCEPTANCE_REPORT.md](P2_ACCEPTANCE_REPORT.md).

P1 remains in progress until tracker continuity and detector quality are checked against annotations, and the raw low-score model-output differences are characterized on representative input. The dynamic IRQ sample is retained with an unresolved later-counter discrepancy and is not treated as utilization evidence. Direct per-core utilization remains unavailable. This report does not mark P2 optimizations or P3 reliability work complete.
